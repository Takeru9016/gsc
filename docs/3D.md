## Architecture Rules

### Hard Rules (never break)
1. **No WebGL on mobile** — detect via `window.WebGLRenderingContext` + user agent. CSS fallback is mandatory on every 3D section.
2. **Build fallback first** — GSAP CSS fallback must exist and be complete before WebGL is added on top.
3. **Progressive enhancement** — WebGL is the enhancement. The page must be fully functional without it.
4. **Never block render** — `<Suspense>` wraps all R3F scenes. Loading fallback is a skeleton or the CSS version.
5. **Performance budget** — WebGL scenes must load in < 100ms (cold), maintain 60fps. If not achievable, simplify geometry.

### Component Structure
```

├── WebGLDetector.tsx        # Detection utility + hook + wrapper
├── SceneCanvas.tsx          # R3F <Canvas> with Suspense + ErrorBoundary
```

### Lenis + GSAP Integration
```typescript
// In (site)/layout.tsx or a dedicated provider
'use client'
import { useEffect } from 'react'
import Lenis from '@studio-freight/lenis'
import { gsap } from 'gsap'
import { ScrollTrigger } from 'gsap/ScrollTrigger'

gsap.registerPlugin(ScrollTrigger)

export function SmoothScrollProvider({ children }: { children: React.ReactNode }) {
  useEffect(() => {
    const lenis = new Lenis({
      duration: 1.2,
      easing: (t) => Math.min(1, 1.001 - Math.pow(2, -10 * t)),
    })

    // Sync Lenis with GSAP ScrollTrigger
    lenis.on('scroll', ScrollTrigger.update)
    gsap.ticker.add((time) => lenis.raf(time * 1000))
    gsap.ticker.lagSmoothing(0)

    return () => {
      lenis.destroy()
      gsap.ticker.remove((time) => lenis.raf(time * 1000))
    }
  }, [])

  return <>{children}</>
}
```

## WebGL Detection

### `components/three/WebGLDetector.tsx`

```typescript
'use client'
import { useState, useEffect, type ReactNode } from 'react'

function detectWebGL(): boolean {
  if (typeof window === 'undefined') return false

  // Check for mobile — no WebGL on mobile regardless of support
  const isMobile = /Android|iPhone|iPad|iPod|Mobile/i.test(navigator.userAgent)
  if (isMobile) return false

  // Check for WebGL support
  try {
    const canvas = document.createElement('canvas')
    return !!(
      window.WebGLRenderingContext &&
      (canvas.getContext('webgl') || canvas.getContext('experimental-webgl'))
    )
  } catch {
    return false
  }
}

export function useWebGL(): boolean {
  const [hasWebGL, setHasWebGL] = useState(false)

  useEffect(() => {
    setHasWebGL(detectWebGL())
  }, [])

  return hasWebGL
}

interface WebGLOnlyProps {
  children: ReactNode
  fallback: ReactNode
}

export function WebGLOnly({ children, fallback }: WebGLOnlyProps) {
  const hasWebGL = useWebGL()
  return <>{hasWebGL ? children : fallback}</>
}
```

## Scene Canvas

### `components/three/SceneCanvas.tsx`

```typescript
'use client'
import { Canvas } from '@react-three/fiber'
import { Suspense, type ReactNode } from 'react'

interface SceneCanvasProps {
  children: ReactNode
  className?: string
  camera?: {
    fov?: number
    position?: [number, number, number]
    near?: number
    far?: number
  }
  dpr?: [number, number]
}

export function SceneCanvas({
  children,
  className,
  camera = { fov: 75, position: [0, 0, 5] },
  dpr = [1, 2],
}: SceneCanvasProps) {
  return (
    <Canvas
      className={className}
      camera={camera}
      dpr={dpr}
      gl={{ antialias: true, alpha: true }}
      style={{ position: 'absolute', inset: 0 }}
    >
      <Suspense fallback={null}>
        {children}
      </Suspense>
    </Canvas>
  )
}
```

## Sports Scroll Experience

### Overview
- GSAP ScrollTrigger **pins** the sports section
- 6 scene groups, each ~100vh of scroll depth
- Scene change: cross-fade between scenes (opacity tween)
- Progress indicator: dots UI overlay (1-6), active dot highlighted
- Total pinned scroll: 600vh (6 × 100vh)

### Scene Layout

```typescript

// - ScrollTrigger pin on container
// - 6 R3F scene groups, only one visible at a time
// - GSAP timeline drives opacity of each group
// - Progress dots UI outside Canvas (HTML overlay)
```

### Scene Specifications

#### Scene 1 — Cricket
```
Camera:   Low angle (y: -1, z: 4), slight upward tilt
Lighting: Key light #FFB300 (gold/warm), fill light #1E88E5 (cool blue)
Elements: Cricket ground plane, stumps geometry, dust particle system
Animation: Slow dust particles rising, stumps cast shadow, ambient rotation of ground
Transition: Fade to Scene 2 on scroll
```

#### Scene 2 — Swimming
```
Camera:   Top-down angle (y: 3, z: 2), looking down
Lighting: Ambient #1E88E5 (pool blue), caustic shader on ground
Elements: Pool lane geometry, caustic light simulation, water surface
Animation: Caustic ripple shader, light refraction movement
Transition: Fade to Scene 3
```

#### Scene 3 — Badminton
```
Camera:   Court-level angle, center court view
Lighting: Fluorescent overhead (white, hard shadows), ambient fill
Elements: Court lines (plane geometry), net, shuttlecock arc trail
Animation: Shuttlecock follows pre-computed arc path with trail renderer
Transition: Fade to Scene 4
```

#### Scene 4 — Tennis
```
Camera:   Side angle, clay court
Lighting: Outdoor warm key (directional), soft ambient
Elements: Clay court texture plane, net, ball with bounce trail
Animation: Ball bounces on clay surface with position + squash/stretch animation
Transition: Fade to Scene 5
```

#### Scene 5 — Squash
```
Camera:   Inside enclosed court, corner angle
Lighting: Overhead fluorescent (enclosed feel), bounce lighting off walls
Elements: Four walls (planes), court lines, ball
Animation: Ball rebounds off walls in randomized pattern, impact burst particles
Transition: Fade to Scene 6
```

#### Scene 6 — Gym
```
Camera:   Low dramatic angle, dark environment
Lighting: #E53935 spot light (red/energy) from above, dark ambient
Elements: Abstract weight geometry (cylinders), energy particle system
Animation: Weights lift/lower cycle, particles surge on lift peak
Transition: Unpin, continue page scroll
```

## Performance Checklist

Run before shipping Phase 3:

```
[ ] WebGL scenes load < 100ms (cold, measured in Chrome DevTools)
[ ] Steady 60fps during scroll (no drops below 55fps on mid-range hardware)
[ ] Total 3D bundle < 500KB gzipped (check with pnpm build --analyze)
[ ] No WebGL rendered on mobile (verify in Chrome DevTools device mode)
[ ] CSS fallback renders correctly on all mobile breakpoints
[ ] No memory leaks — dispose geometries, materials, textures on unmount
[ ] useFrame callbacks are lightweight — no allocations per frame
[ ] Instanced mesh used for particles (never individual meshes for particle systems)
[ ] Textures compressed — use .webp or .ktx2 format, max 512×512 for objects
[ ] prefers-reduced-motion: pause/disable animations when set
```

### Dispose Pattern (prevent memory leaks)

```typescript
import { useEffect } from 'react'
import { useThree } from '@react-three/fiber'

export function CricketBall() {
  const geometry = useMemo(() => new THREE.SphereGeometry(1, 32, 32), [])
  const material = useMemo(() => new THREE.MeshStandardMaterial({ color: '#8B0000' }), [])

  useEffect(() => {
    return () => {
      geometry.dispose()
      material.dispose()
    }
  }, [geometry, material])

  return <mesh geometry={geometry} material={material} />
}
```

## Not Supported — Do Not Attempt

- WebGL on mobile at any point (no exceptions)
- R3F with SSR (always `ssr: false` in dynamic import)
- More than 5000 particles in instanced mesh without profiling
- Three.js OrbitControls (user scrolling controls the scene — not orbit)
- Physics engines (Cannon.js, Rapier) — animations are pre-computed, not simulated
- Post-processing (bloom, depth of field) — performance cost not justified at this scale
